# 风险模型复核：2026-10-08

本报告记录提交8e213c0所对应的旧模型问题。后续v3已修订核心规则，见[risk-model-v3.md](risk-model-v3.md)；诊断脚本打印当前安装代码的model_version，旧模型算例应在8e213c0上复现。

## 结论与范围

用户提供的年度地缘政治风险模型，在“分类强度 + 社会/政治/国际冲突/媒体四维”的结构上，比当前 Beta 的事件类别占比模型更接近所要衡量的地缘风险。当前 Beta 分数尚未完成经验校准，不能仅凭自动化测试通过就宣称排名合理，也不能将它理解为风险概率。

本轮检查生产公式、解析聚合、历史评分与年度原代码，并用实际函数复现下述数值。没有取得两台生产服务器的最新快照或原始事件，故不宣称已经验证某个实际国家的排名。以下数值采用默认 Params；部署端如保存了自定义参数，应以快照 params 再计算。

本轮只修正误导性的指标说明、保存审计与可复现诊断，不更改评分公式，不使现有快照混入未经校准的新模型。

## 当前 Beta 的关键问题

| 问题 | 代码位置与可复现证据 | 影响 |
| --- | --- | --- |
| 国家风险前三项不使用类别强度 | metrics.py 的 country_score_components 只读取类别的 sum_w 占比，没有使用 sum_gold_w | 同一根类别内部的不同 Goldstein 强度不影响这三项；Goldstein 也只是事件类型固定强度，并不表示伤亡规模 |
| 类别重复及遗漏 | root17 同时计入 social 与 political；root15 未计入前三项 | 100条、累计100信源、语调0、动量缺失时，root17总分44.9294，root19总分39.9916，root15总分5.0。属于结构性反例，不是现实国家排名模拟 |
| 曲线饱和过快 | security=100×(1-exp(-r/0.12)) | 安全占比10%、30%、50%、80%分别得到56.5402、91.7915、98.4496、99.8727。高冲突国家间难以区分 |
| 总分混入新闻热度 | momentum_from_coverage 比较全部事件条数 | 基准日均100、最近日300，即得100分动量；即使增加的全是合作事件，也给总分加分。它应是独立的报道活跃度提示 |
| 证据100不等于可信100% | 默认50条事件、累计50信源已达100；GKG46篇文档已达100 | 信源数还是逐事件NumSources累加，没有全球媒体去重；不能表示历史覆盖完整或结论经统计验证 |
| Events 原始语调被截断 | parser.py 先将每条 AvgTone 截断到±10再求和 | 原值-100与+9的均值是-45.5，保留值均值是-0.5；页面原“平均语调”不应被理解为原始字段均值。此为极端合成反例，未估计真实数据影响频率 |
| 企业风险统计普通主题 | parser.py 的 gkg_categories("ECON_TRADE;ENERGY;MEDICAL;")命中经济、基础设施、健康 | 没有区分正常经营活动、利好和风险报道，主题曝光度可能被当成经营风险 |
| 企业百分位丢失差异大小 | percentile_scores([0.0100,0.0101])=[0,100]，未收缩前 | 同一日期只有两个合格国家时，0.01个百分点原始差异可以映射成100分差异；参照国家变化也会导致历史曲线跳变 |

国家前三项“根类别分组重叠”在口径文案中已经公开，但公开说明并不等于该设计已被验证合理。当前企业分数是横截面相对指标，不能把跨日曲线当成风险绝对升降；画均线只能平滑，不能补救定义。

## 对用户年度模型的核验

原件位于 DSI/docs/methodology/source/gdelt_risk_index_b.py 与同目录的 GDELT风险指数构建方法论.md；未修改原件。

原 Python 总分先按社会30%、政治25%、国际冲突25%、媒体20%加权，再按当期国家横截面 Z-score 映射为0–100。DSI 现有 data/risk_monthly/risk_index_2025.csv 的2025年1月含244个唯一国家，按公布四个分项复算该标准化步骤，最大差0.009244分、平均差0.003112分，符合分项及总分只保存两位小数的误差规模。

例如首行叙利亚四项加权原分71.4915，公布总分78.41；这不是加权错误，而是随后标准化的结果。这个核验只证明公布分项到总分的运算一致，不能证明原始事件筛选、月份划分和全部输入正确。月度标准化再做年度平均，也不同于先合并全年事件再算风险。

原模型仍需修订：

- 将141–145全部列作“暴力抗议”，而官方只有145明确指暴力抗议；141是示威、142绝食、143罢工/抵制、144阻塞。
- 国际冲突只保证Actor2非空，Actor1缺失可能仍通过“双方不同”筛选；两方国家代码应均有效。
- 固定频次阈值100/50/80没有随统计时长调整，不能直接复制到小时/日窗口。
- 空国家输入返回50，各类没有相关事件时返回30/25/20等基准；缺采集与确实无相关事件需要分开。
- 方法文档中的本国五年基准、异常值处理、年度月份递增权重等，并未全部落实到原 Python；其实际总分是横截面标准化。各分项和总分也不处于同一标准化尺度。
- eventroot只取首字符是实现错误，但该派生列在当前这些计算中未使用；不应误报为它已导致全部分数错误。

参考：[CAMEO 官方总目录](https://eventdata.parusanalytics.com/cameo.dir/cameocontents.html)、[官方抗议类别说明](https://eventdata.parusanalytics.com/cameo.dir/14protest.html)、[GDELT Events 2.0 字段文档](https://data.gdeltproject.org/documentation/GDELT-Event_Codebook-V2.0.pdf)。

## 建议的修订方式

1. 以用户四维模型为基础，先修订类别、有效行为方与缺失政策；另列新闻活跃度、采集覆盖和样本量，不混为风险。
2. 为年度、滚动30日与实时小时定义明确口径。实时界面可展示最新滚动30日风险与小时新闻量，避免小时少样本独立评分造成跳变。Goldstein度量类别强度，不能冒充真实事件严重程度。
3. 用实际历史样本检查常识排序、轻重冲突区分、媒体规模偏差及缺采集敏感性，再定饱和尺度/权重/参考基准；不要只是把极端国家强行改成预期分数。
4. 固定模型与校准版本；保留当前模型结果用于对照。先验收相同国家、相同日期窗口的新旧模型，再切换发布，重新计算历史趋势。
5. 现有 agg_geo 虽保留类别与部分Goldstein汇总，但没有原年度模型需要的逐事件NumArticles加权、行为方跨国条件与地点联合信息。原始文件已删除，因此无法只换公式就精确重现年度方法。需补充聚合字段并针对需要的历史范围重新读取官方文件，处理完仍删除原始文件；不必在两台机器间传2GB数据库。

## 如何复现与提供实测材料

在 GDELTDataServer 仓库运行（不写数据库、不下载、不停止监控）：

```bash
uv run python scripts/audit_risk_model.py
# 在同时保存了 DSI 源码的机器上，可附加年度结果核验：
uv run python scripts/audit_risk_model.py --annual-csv ../DSI/data/risk_monthly/risk_index_2025.csv
```

实际排名复核只需要最新发布快照和其参数，不需要令牌或完整数据库。工作台“下载快照”即可获取；默认目录为 /opt/GDELTDataServer/data/snapshots/，latest.json 是清单，清单对应 snapshot-*.json.gz 才是结果。若 config.local.json 配置了其他 data_dir，以配置目录为准。完整原始输入复核则另外需要少量指定日期的官方文件。
